How to use 1Router

  1. Add your provider in the Providers tab (with their API key).
  2. Create a 1Router key in the API Keys tab.
  3. Test the model in Try it now below — try an image and each thinking level to see what the provider actually accepts.
  4. Set Model capabilities from what the test proved. Capabilities are only metadata for generated config; they do not change model behavior.
  5. Copy the generated config into your app/tool. Requests and usage then show up in Dashboard.

If something goes wrong

      

        

          
ErrorWhat it means

          
            
401The app is not using a 1Router key. Use a sk-1r-… key from API Keys — not your provider key.

            
400 Unknown modelModel name must be provider/model exactly as shown in the Providers tab.

            
400 … wrong endpointThe model type and endpoint don't match — check the How-to endpoint for its API type.

            
502 Could not reach provider1Router can't reach the provider's Base URL. Check the URL in Providers (and that local servers like Ollama are running).

            
Request works but shows “no usage”The provider didn't report token usage for that request, so there was nothing to count.

Backup & export

      
Download a copy of the SQLite database: providers (including their API keys), client keys, dashboard settings, and full usage history. Login sessions are not included. Keep the file private — treat it like your provider keys. To restore: stop 1Router, replace the database file (data/1router.db by default), and start it again.
